# 智能论文阅读助手（paper-reader-langchain）

> v0.9 ｜ 本地优先的 LLM 论文阅读 Agent

三栏网页阅读器：**LangGraph 状态图编排 + 大小模型协作（本地 Qwen3-4B / 云端 DeepSeek）+ Agentic RAG（跨页语义合并切分）+ 三层记忆（笔记按对话分区增量整理 + 用户画像）**。

核心闭环：**发现（HF 日/周/月热门榜 + arXiv 搜索 + 个性化重排）→ 勾选下载 → 网页阅读 → 选中段落问 AI（混合检索 + 多步 Agent + 流式）→ 图表解读 → 对话整理成笔记（超阈值自动 / 手动，增量问答追加防膨胀，下次讨论自动作背景记忆）→ 跨论文提问行为沉淀为用户画像**

## 功能一览（按使用流程）

### 1. 发现 —— 找论文

- **HF Papers 热门榜**：日/周/月三档（hf-mirror 镜像 API）；**按日期缓存**（今天只爬一次，次日自动刷新），实时抓取失败自动回退当日缓存（前端提示 stale 与缓存时间）
- **arXiv 搜索**：关键词检索（相关度排序），最多 50 条
- **个性化推荐**：由库内文档标题（×3）+ 摘要提取英文关键词生成**推荐兴趣画像**（已读×2 加权、90 天半衰期衰减），候选按 `0.65×兴趣匹配 + 0.35×热度` 重排；前 3 篇标注推荐命中词（纯本地统计，零 token）
- **勾选批量下载** / 直接输入 arXiv ID；arXiv ID + 标题双查重；同 base id 命中时比对 `version + pdf_hash`，**不同版本跳过并提示「未覆盖」**（不静默丢弃）；下载后校验 PDF 完整性
- **启动扫描登记**：服务启动时离线扫 `data/docs/*.pdf`，把历史库清空后遗留的本地 PDF 补登记入库（读元数据猜标题 + 算 pdf_hash，不下载、不建索引，按 arxiv_id 幂等）

### 2. 阅读 —— 读论文

- 三栏布局：左（对话历史 + 文档库）、中（阅读与浏览）、右（问答对话）
- 文档库分区：**未读区 / 已读区 / 目录页**（摘要卡片，标注笔记数与对话数，支持筛选）
- 浏览器内 PDF 翻页缩放（react-pdf）；**选中文字自动生成引用条**，提问时锚定该段落
- **标记已读 / 退回未读 / 删除**（级联清理对话、消息、工具轨迹）

### 3. 问答 —— 问 AI（核心链路）

- SSE 流式输出回答；**引用校验告警**（回答提到未提供的页码时前端提示）与**笔记勘误卡片**在对话区呈现；回答中「第 N 页」可点击，弹层显示对应原文块（`done.citations` 引用回溯）
- 每次提问进入 LangGraph 状态图（见下方架构图）：护栏 →（可选预判）→ 混合检索（RRF）→ Agent 多步推理（统一由 DeepSeek 生成）
- **工具轨迹**：问答过程中实时渲染分步轨迹条（`tool_start`→`tool_end` 事件驱动，显示参数摘要/结果/耗时，`call_id` 一一配对）；**同工具同参运行内复用**（精确调用直接返上次结果，事件带 `cached` 标记、不占执行时延；只缓存成功、失败保留重试语义）；后端全量落库（`tool_steps` 含 `call_id`/`message_id`/完整参数），实时轨迹与历史回放共用同一组件
- （可选）`PREJUDGE_ENABLED=1` 时，本地 4B 先做一次预判——判定寒暄/通用问题跳过检索、并把中文问题改写成英文检索词；因约增加 1.3s 首 token 延迟而改写收益未在回归中体现，**默认关闭**

### 4. 图表解读 —— 看图

- PDF 工具栏「解读本页」：当前页渲染为截图 → DeepSeek vision 流式解读图 / 表 / 公式
- Agent 工具 `look_at_page`：问答中涉及图像细节时由模型自主调用

### 5. 总结与记忆 —— 沉淀讨论

- **整理记忆（增量分区）**：对话太长或结束时点右栏「整理记忆」→ 只吃该对话**水位（`organized_seq`）之后的增量**，把增量整理为**简短一问一答**追加到 `## 对话 <id>` 小节（不碰其他对话小节）；云端为主（一次调用、吃问答前缀缓存），失败转本地 4B 按 `NOTE_BATCH_CHARS≈6000` 分批保底；一次操作完成「Q/A 追加 + 画像更新 + 清账（推进水位 / 删除已整理段 / token 归零）」，幂等可重跑、入口按 `conv_id` 串行
- **自动整理（100k 单线）**：每轮问答按云端实测 `usage.input_tokens` 记账（`last_input_tokens` 覆盖写）；跨过触发线（`ORG_TRIGGER_TOKENS=100000`，总开关 `ORG_AUTO_ENABLED`）即自动整理——**轮末**（回答完成后）后台静默触发；若下一轮提问时仍未完成，**轮前同步等待**（首字延迟红线的唯一声明例外）并向前端发 `organizing` 事件（消息区顶部提示条，首个 `delta`/`done` 到达后清除）；失败不阻断问答、下轮再试
- **笔记 = 记忆文件**：每篇论文一个 Markdown 文件（`data/notes/{arxiv_id}.md`），「笔记」视图可查看 / 编辑 / 保存
- **自动注入**：问答时读取该论文笔记（最新部分，限 4000 字符）注入 Agent 作历史讨论背景——下次聊同一篇论文自然承接上次结论
- **用户画像**：整理记忆的同一次流程顺带归并「这个人怎么问问题」（常问类型 / 常犯误区 / 惯用解释深度）到 `data/notes/_profile.md`（上限 600 字符；云端整理时由云端更新，本地保底时由 4B 离线更新），问答时作背景辅助注入（带防注入定语）；**不加在线调用链**
- **笔记勘误**：注入的记忆可能出错——Agent 发现其与论文原文矛盾时先核实、以论文为准，并调用 `flag_note_issue` 提交勘误建议（只提议不改文件）；对话区渲染勘误卡片，用户点「更正笔记」后经现有保存通道更正（保留原句留痕，下轮问答生效）
- **专注当前论文**：不做跨对话 / 跨文档的记忆召回（场景少、引入杂音，有意去掉）

### 6. 可观测性 —— 复盘

- 全链路埋点：交互 / 本地调用（含 tag、延迟、token）/ API token / 工具成败 / 图级降级原因，经 `GET /api/stats`（7/30 天窗口）聚合查询
- 工具轨迹单独落库（`tool_steps`），支持按对话回放；模型层整理状态（token 水位 / 触发线 / 整理位移 `organized_seq` / 是否在整理）经 `GET /api/conversations/{id}/memory` 查询

## 技术架构

### 技术栈

| 层 | 选型 |
| --- | --- |
| 后端 | FastAPI + uvicorn + SQLite（stdlib，WAL 模式）+ PyMuPDF |
| 编排 | LangGraph 1.x（StateGraph + AsyncSqliteSaver 断点续跑）|
| 检索 | BM25（自实现）+ 词覆盖度 + multilingual-e5-small 稠密向量 → RRF → 直接注入 Agent |
| 模型 | 云端：DeepSeek `deepseek-chat`（问答/整理主路径）/ vision（图表解读）；本地：Qwen3-4B（整理保底/画像/可选预判，bf16 CUDA 常驻）|
| 数据源 | HF Papers（hf-mirror 镜像，日/周/月榜）+ arXiv |
| 前端 | Vite + React 18 + TypeScript + Tailwind v4 + Zustand + react-pdf |

> 显存前提：RTX 4080 Laptop 12GB 上 4B + e5 同卡常驻实测最坏 ≈10GB、余量 ~2GB，故 4B 可安全常驻。

### LangGraph 状态图（`graph.py`）

每次聊天请求进入状态图，每步状态由 checkpointer 落盘（thread_id = conversation_id，失败后传 None 输入即可从断点续跑）：

```
START → guard(规则护栏) → prejudge(本地 4B 预判；默认关闭时直通)
      → retrieve(三通道 RRF Top-12；零命中均匀采样)
      → agent(ReAct 内核，5 工具；注入检索上下文 + 该论文笔记记忆 + 用户画像) → log → END
```

- **5 节点线性图**：`prejudge` 节点用本地 4B 一次调用完成意图路由 + 检索词改写（一次封顶）；`PREJUDGE_ENABLED=0`（默认）时该节点写默认值直通，全链路行为等价 v0.5.4 的 4 节点图
- 所有节点带降级保底（预判失败→默认检索链路；检索异常→转 Agent 工具自救；agent 异常→预检索直达问答）
- 节点经 `get_stream_writer()` 外发 `tool_start / tool_end / delta / retract / note_issue` 事件（`termination` 为内核内部事件，由节点捕获进状态经 `done` 下发）；断连时已流出内容以 `partial` 定稿落库
- **双层对话持久化**：显示层（`chat_messages` + `tool_steps`，完整账本只增不改）与模型层（`model_messages`：user / assistant(含 tool_calls) / tool，供下轮续接、整理时按水位清账）双写落库、下轮各自加载；模型层按轮原子写入（断连整轮不写，序列保持干净）

### 大小模型分工

| 任务 | 执行者 | 在线/离线 | API token |
| --- | --- | --- | --- |
| 相关性排序（RRF） | 本地算法（BM25 + 词覆盖度 + e5 向量） | 在线 | 0 |
| 向量编码（检索） | 本地 e5-small | 在线 | 0 |
| 意图路由 + 检索词改写 | 本地 Qwen3-4B（**默认关闭**，`PREJUDGE_ENABLED=1` 启用） | 在线（一次封顶） | 0 |
| 整理记忆保底（云端失败时分批 Q/A 整理 + 画像更新） | 本地 Qwen3-4B（bf16 CUDA，单例 + 串行锁） | 离线（手动或自动触发的整理流程内） | 0 |
| 问答最终生成 / 图表解读 / 整理记忆主路径（吃前缀缓存） | DeepSeek API | 在线 / 离线（整理） | 有 |

> 设计原则：**所有文字生成的主路径都由 DeepSeek 承担**；本地 4B 只做「信息压缩 + 轻决策」这类零 token 任务，以及云端整理失败时的保底。在线路径**每请求最多一次** 4B 调用（即预判，且默认关闭），整理与画像一律在「整理记忆」流程内完成，绝不占用在线问答链（唯一例外：达阈值时轮前同步等待整理收尾——等的是整理调用，不产生新的在线生成调用）。

### Agentic RAG

1. **三通道检索**：BM25 + 词命中覆盖度 + e5 向量（跨语言：中文问 ↔ 英文论文）→ RRF 融合 Top-12；向量不可用时自动降级纯词法，词法 + 向量均零命中时均匀采样全文块兜底
2. **双路检索（预判开启时）**：词法通道用「原文 + 改写英文词」拼接，向量通道用改写词单独编码（避免中文原文占满 e5 截断窗口把英文关键词切掉）
3. **RRF 排序直接注入**：对 Top-12 按 RRF 分数排序，取前 6 块注入 Agent；引用护栏校验页码引用越界（区间引用 ≥50% 宽容，越界前端提示）
4. **护栏**：ReAct Agent 另有 6 轮步数 / 单轮工具总调用量 10 次 / 文本工具 20s・看图 90s / 300s 整响应超时

> 实验记录：v0.6 曾以 4B 对 RRF Top-12 做列表式重排（F4），gold set 消融显示 Hit@5 0.848→0.818、MRR 0.705→0.618 全面下降，按判停标准（提升 ≥3pp 才转正）**证伪删码**，详见 `test/04-v0.6-回归对比/测评记录.md`。

### ReAct Agent（内核，被图调用）

- **4 只读工具（全部围绕当前论文）**：`search_in_paper`（文内检索）/ `read_page`（读整页）/ `get_outline`（章节目录）/ `look_at_page`（多模态看图）；另有 **`flag_note_issue`**（笔记勘误提议）：发现注入记忆与论文矛盾且已核实时提交，只提议不写文件
- **注入**：模型层历史全量回放 + 该论文笔记记忆 + 用户画像 + 预检索上下文（带【第 N 页】标记）随消息提供，简单问题零工具一轮即答
- **护栏**：单工具连续失败 2 次自动弃用；**步数 ≤6 轮、单轮工具总调用量 ≤10 次、超时**任一触顶即基于已收集信息强制收敛最终回答
- **运行内复用**：同工具同参（精确调用）直接返回运行内缓存结果（`tool_end` 事件带 `cached: true`、延迟 0）；只缓存成功结果，失败保留重试语义

### 记忆体系（三层）

- **短期（模型层）**：每对话全量回放 `model_messages`（append-only、不改写已写入条目，前缀稳定命中云端硬盘缓存、更便宜更快；不做在线裁剪）；历史增长由「整理记忆」统一消化（水位后增量入笔记、已整理段清账）
- **论文级笔记**：单篇一个 md，内部按 `## 对话 <id>` 分区；「整理记忆」只吃每对话水位（`organized_seq`）后的增量，把增量整理为简短 Q/A **追加**到对应小节（云端为主、本地 4B 分批保底、幂等、入口按 conv_id 串行），替代整段重写、防膨胀；问答时读该论文笔记（最新 ≤4000 字符）注入 Agent 作背景；产物可在笔记视图编辑
- **用户画像**：`data/notes/_profile.md`（下划线前缀 = 系统特殊文件，不参与笔记列表/勘误定位），整理记忆时归并提问行为统计（≤600 字符；云端更新为主、4B 保底），问答时小体量注入作辅助背景
- **双画像分清**：`sources.py` 的**推荐兴趣画像**（本地统计、只服务发现页排序）与 `notes.py` 的**用户提问画像**（`_profile.md`、服务问答辅助）是两套独立机制，输入源与用途完全不同
- **有意不做**：跨对话/跨文档记忆召回（噪音大、场景少）；记忆条目化 + ADD/UPDATE/DELETE 四操作（增量追加 + 清账已覆盖膨胀问题）

### 多模态图表解读

PDF 单页渲染（PyMuPDF，最长边 ≈1200px JPEG）→ base64 data URL → DeepSeek vision 流式解读；两个入口共用同一管线：前端「解读本页」按钮（`POST /api/vision_page`）与 Agent `look_at_page` 工具。

### 降级矩阵（工程护栏）

| 环节 | 失败场景 | 兜底行为 |
| --- | --- | --- |
| 护栏 guard | 空消息 | 按问候处理 |
| 预判 prejudge | 关闭 / 超时 / 解析失败 | 写默认值（需检索、不改写），行为等价 v0.5.4 |
| 整体检索 | 异常 | 转 Agent 工具自救（标记 failed） |
| 检索零命中 | 词法 + 向量均无命中 | 均匀采样全文块兜底（防跨语言零召回） |
| Agent | 多步失败 / 超时 / 超调用量 | 降级预检索上下文直达问答 |
| Agent 触顶 | 步数（6）/ 工具总调用（10）/ 整响应超时触顶 | `termination_reason` 显式标记 + 基于已收集信息强制收敛最终回答（不空手） |
| 客户端断连 | SSE 连接中断 | 已流出内容 `partial` 定稿落库（`status=partial` 即中断标志）；模型层该轮原子不写 |
| 图表解读 | 渲染或模型失败 | 转为提示文本，不中断 SSE |
| 笔记记忆读取 | 文件不存在 / 目录异常 | 返回空串，跳过注入不阻断问答 |
| 用户画像读取 | 无文件 / 关闭 | 返回空串，不注入 |
| 整理记忆 | 云端失败 | 转本地 4B 分批保底；双失败笔记与水位均不动、返回 502 提示 |
| 自动整理 | 后台 / 轮前触发失败 | 仅记录 warning，不阻断本轮回答；水位不动、下轮再试（幂等重跑） |
| 画像更新 | 模型 / 写入失败 | 保留旧画像，静默不阻断（不影响 Q/A 落盘与清账） |

## 快速开始

```bash
# 1. Python 依赖（含 torch/transformers，建议 Python 3.10+）
pip install -r requirements.txt

# 2. 本地模型放入 models/（可从 HF 镜像下载；缺失时自动降级为纯云端 + 词法检索）
#    models/Qwen3-4B/（本地 LLM，默认）与 models/multilingual-e5-small/（向量）
#    显存紧张可用 LOCAL_LLM_NAME=Qwen3-1.7B 切到更轻的模型

# 3. 配置 .env（模板已带默认值，核心是 DEEPSEEK_API_KEY）

# 4. 构建前端并启动（自动托管，访问 http://127.0.0.1:8000）
cd frontend && npm install && npm run build && cd ..
python main.py
```

- 前端开发模式：`cd frontend && npm run dev`（访问 5173，`/api` 自动代理到 8000）
- 数据持久化：文档/对话/埋点存于 `data/db/app.db`（WAL，重启不丢）；**笔记存于 `data/notes/{arxiv_id}.md`**（含系统文件 `_profile.md`）；PDF 存 `data/docs/`；检索索引为进程内缓存，重启重建
- 未配置本地模型或 `LOCAL_LLM_ENABLED=0` 时，整理记忆仅云端路径（云端失败无本地保底；问答本身由 DeepSeek 承担，功能可用）
- 测评回归：`python "test/10-测评体系/run_all.py"`（默认 10 套件，自动生成指标报告，详见「测评体系」）

## 使用指南（首次体验路径）

1. **发现**：进入「发现」视图 → 切换 HF 日/周/月榜或搜索 arXiv → 勾选候选 → 「下载入库」
2. **阅读**：打开「文档库」→ 目录页/未读区点击论文进入阅读器；翻页缩放浏览
3. **提问**：右栏输入问题；或先在 PDF 中选中一段文字再提问（自动锚定引用）→ 观察流式回答与引用校验告警
4. **看图**：「解读本页」按钮解读当前页图表；或在提问中要求「看看第 N 页的图」，Agent 会自主调用工具
5. **沉淀**：聊到一定程度点右栏「整理记忆」→ 增量对话整理为 Q/A 追加进笔记（可去「笔记」视图修改），并顺带更新用户画像；下次就同一篇论文提问时自动作为背景注入
6. **长对话**：模型层历史持续增长时点「整理记忆」统一消化（Q/A 追加笔记 + 已整理段清账，显示层不受影响）；打开左侧历史对话可回放工具轨迹
