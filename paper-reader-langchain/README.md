# 智能论文阅读助手（paper-reader-langchain）

> v0.6 ｜ 本地优先的 LLM 论文阅读 Agent

三栏网页阅读器：**LangGraph 状态图编排 + 大小模型协作（本地 Qwen3-4B / 云端 DeepSeek）+ Agentic RAG + 三层记忆（笔记合并重写 + 用户画像）**。

核心闭环：**发现（HF 日/周/月热门榜 + arXiv 搜索 + 个性化重排）→ 勾选下载 → 网页阅读 → 选中段落问 AI（混合检索 + 多步 Agent + 流式）→ 图表解读 → 对话整理成笔记（合并重写防膨胀，下次讨论自动作背景记忆）→ 跨论文提问行为沉淀为用户画像**

## 亮点速览

| # | 亮点 | 说明 |
| --- | --- | --- |
| 1 | LangGraph 状态图编排 | 5 节点线性架构（guard→prejudge→retrieve→agent→log），AsyncSqliteSaver 每步落盘，失败可断点续跑；`prejudge`（本地小模型预判）默认关闭，关闭时行为与 4 节点链路完全等价 |
| 2 | 大小模型分工 | 本地 Qwen3-4B 专责「信息压缩 + 轻决策」（对话总结、笔记合并、用户画像提炼；可选的意图路由/检索词改写），零 API token；所有文字生成（问答/图表解读）由 DeepSeek 承担 |
| 3 | Agentic RAG | BM25 + 词覆盖度 + e5 稠密向量三通道 → RRF 融合 Top-12 → 直接注入 Agent（无精排评分，响应更快）；可选双路检索（向量通道用改写词单独编码，规避中文原文占满 e5 截断窗口） |
| 4 | 护栏式 ReAct Agent | 5 工具（4 只读查论文 + 1 笔记勘误提议）自主多步推理；三重上限——**6 轮步数 / 单轮工具总调用量 10 次 / 文本工具 20s・看图 90s・整响应 300s 超时**；工具连续失败自动弃用、超限强制收敛 |
| 5 | 三层记忆 + 勘误闭环 | **短期**（最近 8 条消息窗口）+ **论文级笔记**（「整理记忆」把旧笔记与本次对话**合并重写**为一份完整笔记，替代无限追加）+ **用户画像**（`_profile.md`，跨论文提问行为统计）；问答时笔记与画像作背景注入；Agent 发现笔记与论文矛盾时提交勘误建议，用户确认后更正（原句留痕） |
| 6 | 全链路降级保底 | 每个节点、每次模型/网络故障都有兜底路径（见「降级矩阵」），新功能失败一律退回 v0.5.4 行为，服务不中断 |
| 7 | 多模态图表解读 | PDF 单页渲染 → DeepSeek vision 流式解读；工具栏按钮 + Agent `look_at_page` 工具双入口 |
| 8 | 可观测性与可评测 | 全链路埋点（本地/API/工具/交互）经 `/api/stats` 聚合；含检索 gold set（33 例）与端到端用例集（38 例），支持版本回归对比（`test/`） |
| 9 | 代码精简优化 | v0.5 模块合并（16→10）+ 删除精排评分/闲聊分流/跨文档检索等过度设计；v0.6 实验（4B 列表式重排）经评测证伪后按判停标准删码、不留死分支 |

## 功能一览（按使用流程）

### 1. 发现 —— 找论文

- **HF Papers 热门榜**：日/周/月三档（hf-mirror 镜像 API）；**按日期缓存**（今天只爬一次，次日自动刷新），实时抓取失败自动回退当日缓存（前端提示 stale 与缓存时间）
- **arXiv 搜索**：关键词检索（相关度排序），最多 50 条
- **个性化推荐**：由库内文档标题（×3）+ 摘要提取英文关键词生成**推荐兴趣画像**（已读×2 加权、90 天半衰期衰减），候选按 `0.65×兴趣匹配 + 0.35×热度` 重排；前 3 篇标注推荐命中词（纯本地统计，零 token）
- **勾选批量下载** / 直接输入 arXiv ID；arXiv ID + 标题双查重（重复自动跳过）；下载后校验 PDF 完整性

### 2. 阅读 —— 读论文

- 三栏布局：左（对话历史 + 文档库）、中（阅读与浏览）、右（问答对话）
- 文档库分区：**未读区 / 已读区 / 目录页**（摘要卡片，标注笔记数与对话数，支持筛选）
- 浏览器内 PDF 翻页缩放（react-pdf）；**选中文字自动生成引用条**，提问时锚定该段落
- **标记已读 / 退回未读 / 删除**（级联清理对话、消息、工具轨迹）

### 3. 问答 —— 问 AI（核心链路）

- SSE 流式输出回答；**引用校验告警**（回答提到未提供的页码时前端提示）与**笔记勘误卡片**在对话区呈现
- 每次提问进入 LangGraph 状态图（见下方架构图）：护栏 →（可选预判）→ 混合检索（RRF）→ Agent 多步推理（统一由 DeepSeek 生成）
- **工具轨迹**：后端对每次检索/工具/降级全量埋点并落库（`agent_steps`），可经 `GET /api/conversations/{id}/steps` 与 `/api/stats` 观测；当前前端问答区聚焦流式回答，未渲染分步轨迹时间线
- （可选）`PREJUDGE_ENABLED=1` 时，本地 4B 先做一次预判——判定寒暄/通用问题跳过检索、并把中文问题改写成英文检索词；因约增加 1.3s 首 token 延迟而改写收益未在回归中体现，**默认关闭**

### 4. 图表解读 —— 看图

- PDF 工具栏「解读本页」：当前页渲染为截图 → DeepSeek vision 流式解读图 / 表 / 公式
- Agent 工具 `look_at_page`：问答中涉及图像细节时由模型自主调用

### 5. 总结与记忆 —— 沉淀讨论

- **整理记忆（合并重写）**：对话太长或结束时点右栏「整理记忆」→ 本地 4B 把**旧笔记 + 本次对话**合并为一份完整笔记（同义结论去重、矛盾保留较新一条并标注、上限 `NOTE_MAX_CHARS≈2500`），**替代无限追加**、防止笔记膨胀；合并失败/超时退回追加旧逻辑
- **笔记 = 记忆文件**：每篇论文一个 Markdown 文件（`data/notes/{arxiv_id}.md`），「笔记」视图可查看 / 编辑 / 保存
- **自动注入**：问答时读取该论文笔记（最新部分，限 4000 字符）注入 Agent 作历史讨论背景——下次聊同一篇论文自然承接上次结论
- **用户画像**：整理记忆的同一次离线流程顺带让 4B 增量归并「这个人怎么问问题」（常问类型 / 常犯误区 / 惯用解释深度）到 `data/notes/_profile.md`（上限 600 字符），问答时作背景辅助注入（带防注入定语）；**不加在线调用链**
- **笔记勘误**：注入的记忆可能出错——Agent 发现其与论文原文矛盾时先核实、以论文为准，并调用 `flag_note_issue` 提交勘误建议（只提议不改文件）；对话区渲染勘误卡片，用户点「更正笔记」后经现有保存通道更正（保留原句留痕，下轮问答生效）
- **专注当前论文**：不做跨对话 / 跨文档的记忆召回（场景少、引入杂音，有意去掉）

### 6. 可观测性 —— 复盘

- 全链路埋点：交互 / 本地调用（含 tag、延迟、token）/ API token / 工具成败 / 图级降级原因，经 `GET /api/stats`（7/30 天窗口）聚合查询
- 工具轨迹单独落库（`agent_steps`），支持按对话回放

## 技术架构

### 技术栈

| 层 | 选型 |
| --- | --- |
| 后端 | FastAPI + uvicorn + SQLite（stdlib，WAL 模式）+ PyMuPDF |
| 编排 | LangGraph 1.x（StateGraph + AsyncSqliteSaver 断点续跑）|
| 检索 | BM25（自实现）+ 词覆盖度 + multilingual-e5-small 稠密向量 → RRF → 直接注入 Agent |
| 模型 | 云端：DeepSeek `deepseek-chat`（问答）/ vision（图表解读）；本地：Qwen3-4B（总结/合并/画像/可选预判，bf16 CUDA 常驻）|
| 数据源 | HF Papers（hf-mirror 镜像，日/周/月榜）+ arXiv |
| 前端 | Vite + React 18 + TypeScript + Tailwind v4 + Zustand + react-pdf |

> 显存前提：RTX 4080 Laptop 12GB 上 4B + e5 同卡常驻实测最坏 ≈10GB、余量 ~2GB，故 4B 可安全常驻。

### LangGraph 状态图（`graph.py`）

每次聊天请求进入状态图，每步状态由 checkpointer 落盘（thread_id = conversation_id，失败后传 None 输入即可从断点续跑）：

```
START → guard(规则护栏) → prejudge(本地 4B 预判；默认关闭时直通)
      → retrieve(三通道 RRF Top-12；零命中均匀采样)
      → agent(ReAct 内核，5 工具；注入检索上下文 + 该论文笔记记忆 + 用户画像) → log → END
```

- **5 节点线性图**：`prejudge` 节点用本地 4B 一次调用完成意图路由 + 检索词改写（一次封顶）；`PREJUDGE_ENABLED=0`（默认）时该节点写默认值直通，全链路行为等价 v0.5.4 的 4 节点图
- 所有节点带降级保底（预判失败→默认检索链路；检索异常→转 Agent 工具自救；agent 异常→预检索直达问答）
- 节点经 `get_stream_writer()` 外发 `agent_step / agent_observation / delta / note_issue` 事件（后端全量埋点，前端聚焦 `delta/done/note_issue` 呈现）

### 大小模型分工

| 任务 | 执行者 | 在线/离线 | API token |
| --- | --- | --- | --- |
| 相关性排序（RRF） | 本地算法（BM25 + 词覆盖度 + e5 向量） | 在线 | 0 |
| 向量编码（检索） | 本地 e5-small | 在线 | 0 |
| 意图路由 + 检索词改写 | 本地 Qwen3-4B（**默认关闭**，`PREJUDGE_ENABLED=1` 启用） | 在线（一次封顶） | 0 |
| 对话总结 / 笔记合并 / 用户画像提炼 | 本地 Qwen3-4B（bf16 CUDA，单例 + 串行锁） | 离线（用户触发整理记忆时） | 0 |
| 问答最终生成 / 图表解读 | DeepSeek API | 在线 | 有 |

> 设计原则：**所有文字生成都由 DeepSeek 承担**；本地 4B 只做「信息压缩 + 轻决策」这类零 token 任务。在线路径**每请求最多一次** 4B 调用（即预判，且默认关闭），画像/总结/合并一律在离线的「整理记忆」流程内完成，绝不占用在线问答链。

### Agentic RAG

1. **三通道检索**：BM25 + 词命中覆盖度 + e5 向量（跨语言：中文问 ↔ 英文论文）→ RRF 融合 Top-12；向量不可用时自动降级纯词法，词法 + 向量均零命中时均匀采样全文块兜底
2. **双路检索（预判开启时）**：词法通道用「原文 + 改写英文词」拼接，向量通道用改写词单独编码（避免中文原文占满 e5 截断窗口把英文关键词切掉）
3. **RRF 排序直接注入**：对 Top-12 按 RRF 分数排序，取前 6 块注入 Agent；引用护栏校验页码引用越界（区间引用 ≥50% 宽容，越界前端提示）
4. **护栏**：ReAct Agent 另有 6 轮步数 / 单轮工具总调用量 10 次 / 文本工具 20s・看图 90s / 300s 整响应超时

> 实验记录：v0.6 曾以 4B 对 RRF Top-12 做列表式重排（F4），gold set 消融显示 Hit@5 0.848→0.818、MRR 0.705→0.618 全面下降，按判停标准（提升 ≥3pp 才转正）**证伪删码**，详见 `test/10-v0.6回归对比/测评记录.md`。

### ReAct Agent（内核，被图调用）

- **4 只读工具（全部围绕当前论文）**：`search_in_paper`（文内检索）/ `read_page`（读整页）/ `get_outline`（章节目录）/ `look_at_page`（多模态看图）；另有 **`flag_note_issue`**（笔记勘误提议）：发现注入记忆与论文矛盾且已核实时提交，只提议不写文件
- **注入**：短期记忆（最近消息窗口原文）+ 该论文笔记记忆 + 用户画像 + 预检索上下文（带【第 N 页】标记）随消息提供，简单问题零工具一轮即答
- **护栏**：单工具连续失败 2 次自动弃用；**步数 ≤6 轮、单轮工具总调用量 ≤10 次、超时**任一触顶即基于已收集信息强制收敛最终回答

### 记忆体系（三层）

- **短期**：每对话取最近 8 条消息原文；构建失败回退最近历史
- **论文级笔记**：「整理记忆」把当前对话与旧笔记**合并重写**为一份完整笔记（防无限膨胀）；问答时读该论文笔记（最新 ≤4000 字符）注入 Agent 作背景；产物可在笔记视图编辑
- **用户画像**：`data/notes/_profile.md`（下划线前缀 = 系统特殊文件，不参与笔记列表/勘误定位），整理记忆时离线增量归并提问行为统计（≤600 字符），问答时小体量注入作辅助背景
- **双画像分清**：`sources.py` 的**推荐兴趣画像**（本地统计、只服务发现页排序）与 `notes.py` 的**用户提问画像**（`_profile.md`、服务问答辅助）是两套独立机制，输入源与用途完全不同
- **有意不做**：跨对话/跨文档记忆召回（噪音大、场景少）；记忆条目化 + ADD/UPDATE/DELETE 四操作（合并重写已覆盖 80% 膨胀问题）

### 多模态图表解读

PDF 单页渲染（PyMuPDF，最长边 ≈1200px JPEG）→ base64 data URL → DeepSeek vision 流式解读；两个入口共用同一管线：前端「解读本页」按钮（`POST /api/vision_page`）与 Agent `look_at_page` 工具。

### 降级矩阵（工程护栏）

| 环节 | 失败场景 | 兜底行为 |
| --- | --- | --- |
| 护栏 guard | 空消息 | 按问候处理 |
| 预判 prejudge | 关闭 / 超时 / 解析失败 | 写默认值（需检索、不改写），行为等价 v0.5.4 |
| 整体检索 | 异常 | 转 Agent 工具自救（标记 failed） |
| 检索零命中 | 词法 + 向量均无命中 | 均匀采样全文块兜底（防跨语言零召回） |
| Agent | 多步失败 / 超时 / 超调用量 | 降级预检索上下文直达问答 |
| 图表解读 | 渲染或模型失败 | 转为提示文本，不中断 SSE |
| 笔记记忆读取 | 文件不存在 / 目录异常 | 返回空串，跳过注入不阻断问答 |
| 用户画像读取 | 无文件 / 关闭 | 返回空串，不注入 |
| 总结整理 | 合并失败 / 超时 | 退回追加逻辑；写入失败返回错误提示，不影响对话 |
| 画像更新 | 模型 / 写入失败 | 保留旧画像，静默不阻断 |

## 快速开始

```bash
# 1. Python 依赖（含 torch/transformers，建议 Python 3.10+）
pip install -r requirements.txt

# 2. 本地模型放入 models/（可从 HF 镜像下载；缺失时自动降级为纯云端 + 词法检索）
#    models/Qwen3-4B/（本地 LLM，默认）与 models/multilingual-e5-small/（向量）
#    显存紧张可用 LOCAL_LLM_NAME=Qwen3-1.7B 切到更轻的模型

# 3. 配置 .env（模板已带默认值，核心是 DEEPSEEK_API_KEY）

# 4. 构建前端并启动（自动托管，访问 http://127.0.0.1:8000）
cd frontend && npm install && npm run build && cd ..
python main.py
```

- 前端开发模式：`cd frontend && npm run dev`（访问 5173，`/api` 自动代理到 8000）
- 数据持久化：文档/对话/埋点存于 `data/db/app.db`（WAL，重启不丢）；**笔记存于 `data/notes/{arxiv_id}.md`**（含系统文件 `_profile.md`）；PDF 存 `data/docs/`；检索索引为进程内缓存，重启重建
- 未配置本地模型或 `LOCAL_LLM_ENABLED=0` 时，总结/合并/画像走保底路径（问答本身由 DeepSeek 承担，功能可用）

## 使用指南（首次体验路径）

1. **发现**：进入「发现」视图 → 切换 HF 日/周/月榜或搜索 arXiv → 勾选候选 → 「下载入库」
2. **阅读**：打开「文档库」→ 目录页/未读区点击论文进入阅读器；翻页缩放浏览
3. **提问**：右栏输入问题；或先在 PDF 中选中一段文字再提问（自动锚定引用）→ 观察流式回答与引用校验告警
4. **看图**：「解读本页」按钮解读当前页图表；或在提问中要求「看看第 N 页的图」，Agent 会自主调用工具
5. **沉淀**：聊到一定程度点右栏「整理记忆」→ 对话与旧笔记合并为一份笔记（可去「笔记」视图修改），并顺带更新用户画像；下次就同一篇论文提问时自动作为背景注入

## API 一览

| 端点 | 作用 |
| --- | --- |
| `POST /api/discover` | 获取候选：`{source: hf_papers, period: daily\|weekly\|monthly}`（榜单 + 个性化重排，抓取失败回退缓存并给 `stale` 标记）或 `{source: arxiv, query}` |

| `POST /api/conversations/{id}/summarize` | 整理记忆：旧笔记与对话合并重写为一份笔记（并顺带更新用户画像） |
| `GET /api/conversations?doc_id=` / `.../{id}/messages` | 对话历史 |
| `GET /api/conversations/{id}/steps` | 会话工具轨迹（agent_steps） |
| `GET /api/notes` `/api/notes/{arxiv_id}` | 笔记列表（可 ?doc_id=）/ 详情 |
| `POST /api/notes/{arxiv_id}` / `DELETE /api/notes/{arxiv_id}` | 保存笔记（不存在自动创建）/ 删除笔记 |
| `POST /api/vision_page` | SSE 图表解读：页面渲染 → vision 流式（`meta/delta/done`） |
| `GET /api/stats?days=` | 埋点聚合（事件/模型调用/token/工具与任务细分） |
| `GET /api/health` | 健康检查（云端 LLM + 本地模型 + 多模态状态） |

## 版本路线

- **v2**：段落级分块 + BM25/RRF 混合检索；引用校验护栏
- **v3**：护栏式 ReAct Agent（多工具多步循环、轨迹时间线、异常降级）
- **v4**：LangGraph 编排（单轮检索评分 / 断点续跑）；1.7B 控制层 + e5 混合检索
- **v0.4.0**：删除 QA 缓存系统；inline 检索上下文构建逻辑
- **v0.4.1**：HF 周/月热门榜 + 抓取失败兜底缓存；关键词画像个性化推荐；笔记文件化存储
- **v0.4.2**：修复笔记链路（路由/创建/查询/计数）；看图工具超时放宽（90s）；死代码清理
- **v0.4.3**：删除闲聊分流与意图分类（5 节点线性图，小模型只做相关性评分）；Agent 工具收敛为单篇论文 4 工具；记忆体系重构（「总结整理」→ 笔记 → 自动注入，移除跨对话召回与偏好表）
- **v0.5.0**：模块合并 16→10（图三合一 graph.py；笔记 + 记忆 → notes.py；e5 向量并入 documents.py；本地 1.7B 并入 llm.py）；精排与评分合并为一次「打分即排序」（省一次本地推理）；删除 pick_context 等约 90 行旧逻辑
- **v0.5.1**：清理数据库废弃表（notes/conv_summaries/qa_cache/memories）及级联死代码，不再兼容 v4 历史数据
- **v0.5.2**：删除 1.7B 相关性评分功能（延迟高、收益低），改为纯 RRF 排序；本地模型专用于对话总结（离线任务，零 Token）；LangGraph 从 5 节点简化为 4 节点（响应更快）
- **v0.5.3**：笔记勘误闭环——注入记忆升级为「可能有误、以论文为准」；新增 `flag_note_issue` 工具（核实矛盾后提交勘误建议，只提议不写文件）+ `note_issue` 事件 + 前端勘误卡片；用户确认后经现有保存通道更正（保留原句留痕）
- **v0.5.4**：端到端测试修复——「解读本页」不再因普通问答误显「解读中…」（streamKind 区分生成类型）；笔记页「返回阅读」失效修复（改挂 store 视图切换）；ReAct 工具轮过渡语泄漏修复（新增 `retract` 事件回退误转发文本）；窄窗口布局防挤压（根容器最小宽度 + 工具栏单行横向滚动）
- **v0.6.0（当前）**：本地模型切 **Qwen3-4B**（4B+e5 常驻实测 ~10/12GB）；**F0** 工具总调用量护栏（修 G01/E13）；**F2** 新增 `prejudge` 图节点（本地 4B 一次调用意图路由 + 检索词改写，因延迟/收益比默认关闭）；**F3** 笔记合并重写（防无限膨胀）+ 用户画像 `_profile.md`（离线整理记忆时更新、问答辅助注入）；**F4** 4B 列表式重排实验经评测证伪后按判停标准删码。**回归**：检索 Hit@5 0.848 无退化，端到端 38 例 31→36 通过（G01/E13/T05/T06/E06 转 PASS，零退化），详见 `test/10-v0.6回归对比/测评记录.md`
